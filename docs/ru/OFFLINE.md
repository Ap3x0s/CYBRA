# Офлайн-установка

На серверах в сети заказчика нет доступа в интернет. Эта страница описывает,
как поставить тяжёлые бенчмарки — garak, PyRIT, AgentDojo, BIPIA, promptfoo —
на такую машину.

Само приложение, его датасеты и образ консоли интернета не требуют. Он нужен
только этим пяти инструментам.

Образ интернета не требует, но попасть на машину ему надо. `docker pull` из
изолированной сети до Docker Hub не достучится, поэтому образ едет файлом:

```bash
# на машине с интернетом
docker pull ap3x0/cybra:latest
docker save ap3x0/cybra:latest -o cybra-image.tar

# на изолированном хосте
docker load -i cybra-image.tar
```

Оба файла — и образ, и bundle — едут на одном носителе.

## Как это устроено

Bundle собирается один раз на машине **с** интернетом, переносится, и
установка идёт из него. Что нужно знать заранее — две вещи:

| Что | Почему важно |
|-----|--------------|
| Целевая ОС | Колёса для Windows не встанут на Linux и наоборот |
| Версия Python | Колёса собираются под конкретную минорную версию; цель — **3.12** |

Обе записываются в bundle, вместе с SHA256 по каждому файлу.

## Сборка bundle

На машине с интернетом и склонированным репозиторием:

```bash
# для Linux
python scripts/build_offline_bundle.py --platform linux

# для Windows
python scripts/build_offline_bundle.py --platform windows

# только часть, чтобы было меньше
python scripts/build_offline_bundle.py --platform linux --tools garak promptfoo
```

Результат:

```
offline-bundle/
├── wheels/       колёса Python под целевую платформу
├── sources/      архивы инструментов, которые ставятся с git
├── npm/          кеш npm для promptfoo
├── MANIFEST.json платформа, версии, SHA256 по каждому файлу
├── SHA256SUMS    для `sha256sum -c`
└── README.txt    короткая инструкция, которую отдают вместе с bundle
```

Ожидаемый вес: **~515 МБ для Linux**, ~720 МБ если везти и Windows-вариант
PyRIT. Почти всё — `torch`, около 514 МБ до сжатия. Со всеми инструментами и
кешем npm выходит ~1.9 ГБ.

## Установка у заказчика

```bash
export CYBRA_OFFLINE_DIR=/opt/cybra/offline-bundle
cybra setup --tools garak pyrit agentdojo bipia promptfoo
```

На Windows переменная задаётся иначе: `export` — встроенная команда POSIX-шелла,
в `cmd.exe` и PowerShell её нет:

```powershell
$env:CYBRA_OFFLINE_DIR = 'D:\cybra\offline-bundle'   # PowerShell
```

```cmd
set CYBRA_OFFLINE_DIR=D:\cybra\offline-bundle        :: cmd.exe
```

В обоих случаях значение живёт до конца сессии. `setx` его закрепит, но
заодно подмешает всем последующим процессам — для разовой установки это
редко нужно.

С заданным `CYBRA_OFFLINE_DIR` сеть не используется:

| Что | Как ставится офлайн |
|-----|---------------------|
| Python-пакеты | `--no-index --find-links=<bundle>/wheels` |
| garak, PyRIT, AgentDojo | git-строки в `locks/*.txt` заменяются на локальные архивы из `<bundle>/sources` |
| BIPIA | 28 колёс из `locks/bipia.txt`, ставятся в основное окружение |
| promptfoo | `npm ci --offline --cache=<bundle>/npm` |

Оба написания команды работают; флаг — то, что используется во всём
интерфейсе и документации:

```bash
cybra setup --tools garak pyrit    # с флагом
cybra setup garak pyrit            # то же, позиционно
cybra setup                        # garak, PyRIT, AgentDojo, promptfoo
```

Обратите внимание на последнюю строку: `cybra setup` без имён ставит четыре
инструмента, **не** BIPIA. BIPIA — единственный, который надо назвать явно:

```bash
cybra setup --tools bipia
```

Установщик печатает режим до начала работы — сразу видно, пойдёт ли он
в сеть:

```
Режим: офлайн
  bundle : /opt/cybra/offline-bundle
  колёс  : 184
  архивов: 3
  npm    : есть
  сеть не используется
```

Без `CYBRA_OFFLINE_DIR` будет `Режим: онлайн (PyPI + npm)` — это и есть
признак того, что на машине без интернета установка уйдёт в таймауты.

Строка про архивы — то, что легко упустить, поэтому скажем прямо. `garak` в
lock-файле закреплён git-ссылкой:

```
garak @ git+https://github.com/NVIDIA/garak.git@93aa9cdec309...
```

`--no-index` на неё **не действует**: он ограничивает поиск на индексе, а
git-ссылка обрабатывается отдельным механизмом, который клонирует
репозиторий. Без подмены установка на машине без интернета падала бы на этой
строке, хотя `sources/garak-*.tar.gz` лежит рядом.

Поэтому `cybra setup` переписывает такие строки во временный файл
`<tool>.offline.txt` и ставит из локальных архивов. Если архива в bundle нет,
строка остаётся как есть и установка падает с понятной ошибкой: инструмент,
который молча пропустил свою цель, хуже явного отказа.

Перед установкой стоит проверить целостность:

```bash
cd /opt/cybra/offline-bundle
sha256sum -c SHA256SUMS
```

## Повторный запуск после неудачной попытки

На Windows недоустановленный каталог `.tools/<tool>` не всегда удаляется:
антивирус, индексатор поиска или только что завершившийся pip держат файлы
`.pyd` и `.dll`, и удаление отвечает «Отказано в доступе». После этого
`uv venv` отказывается работать с существующим каталогом, и повтор
невозможен.

`cybra setup` это переживает: сначала повторяет удаление, а если файлы всё
ещё заняты — переименовывает каталог в сторону и создаёт окружение заново.
Оставшийся `<tool>.stale-<время>` можно удалить позже, когда антивирус
закончит.

Если прогон упал по другой причине — просто запустите ту же команду снова.
Установка идёт по инструментам, и сбой одного не мешает остальным.

## Какие бенчмарки затронуты

В поставке восемь бенчмарков. Bundle не нужен только трём из них:

| Бенчмарк | Как ставится | Нужен bundle |
|----------|--------------|--------------|
| HarmBench, JailbreakBench, Security Regression | чистый Python, входит в образ | нет |
| BIPIA | код в `vendor/bipia` + 28 колёс из `locks/bipia.txt` | **да** |
| garak | git + 174 колёса | **да** |
| PyRIT | git + 108 колёс | **да** |
| AgentDojo | git + 70 колёс | **да** |
| promptfoo | npm-пакет | **да** |

BIPIA — та, где легко ошибиться. `vendor/bipia` — это апстримные сборщики
данных, перенесённые без изменений и лежащие в образе. Но импорт
`bipia.data` тянет ещё `pandas`, `jsonlines`, `nltk` и `transformers`,
которых в образе **нет**. Консоль показывает разрыв честно: эти четыре
импорта проверяются до старта прогона, и BIPIA отображается как
неустановленная с подсказкой `cybra setup --tools bipia`. Называть её надо
явно — `cybra setup` без имён её не ставит.

Значит поставке, которая гоняет только HarmBench, JailbreakBench и Security
Regression, bundle не нужен вовсе.

## Требования к целевой машине

- **glibc 2.28 или новее** для Linux — Debian 10+, Ubuntu 20.04+, RHEL 8+.
  Проверка: `ldd --version`. Более старые системы не поддерживаются: для них
  не публикуются колёса актуальных numpy и torch.
- **Python 3.12** для процесса приложения. Колёса в bundle собраны под cp312.
- **Node.js 22+**, если в поставке нужен promptfoo.
- `uv` — `cybra setup` использует его для создания отдельных окружений.
  **Отдельно ставить не нужно, если есть bundle**: версия под целевую
  платформу лежит внутри `wheels/`, и установщик поставит её сам, если
  uv не найден. На машине с интернетом достаточно `pip install uv`.

## Проверка, что офлайн действительно работает

Этот шаг обязателен. На машине, где пакеты уже лежат в кеше pip, всё
«заработает» и без всякого bundle — такая проверка не доказывает ничего.

1. Взять чистую машину, VM или контейнер.
2. Отключить сеть полностью — `ip link set eth0 down` или отсутствие
   интерфейса вовсе. Не прокси, а именно сеть.
3. Перенести bundle, выполнить `sha256sum -c`, затем `cybra setup`.
4. Прогнать бенчмарк до конца.
5. Убедиться, что наружу никто не стучался: в выводе `cybra setup` и в
   логах инструментов не должно быть сетевых ошибок.

## Известные ограничения

- Bundle **привязан к платформе и версии Python**. Один bundle не покроет и
  Linux, и Windows — собирать два.
- В `sources/` лежат архивы инструментов из git. Нужны более новые версии —
  пересобрать bundle, а не править его на месте.
- Версии колёс фиксируются файлами `locks/*.txt`. Смена версии означает
  пересборку.
- Для многих машин и частых обновлений лучше подходит внутренний репозиторий
  (devpi для Python, Verdaccio для npm), а не файлы. Файлы удобны для
  разовой установки.
