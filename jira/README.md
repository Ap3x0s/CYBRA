# Канбан CYBRA в Jira

Проект **CYB** — «CYBRA», company-managed, kanban. Доска: `CYB board`.

## Что создано автоматически

| Сущность | Значение |
|---|---|
| Проект | `CYB` (id 10035), тип software, шаблон kanban |
| Доска | `CYB board` (agile board id 36), фильтр по проекту |
| Эпики | CYB-1 … CYB-5 |
| Истории | CYB-6 … CYB-33 (28 штук), привязаны к эпикам через parent |

Скрипт идемпотентен по summary: повторный запуск не создаёт дублей.

## Как воспроизвести с нуля

```bash
export JIRA_BASE=https://your-domain.atlassian.net
export JIRA_EMAIL=you@example.com
export JIRA_TOKEN=ATATT...

cd jira
python jira_import.py --dry-run     # посмотреть план
python jira_import.py               # создать эпики и истории
```

Токен создаётся на https://id.atlassian.com/manage-profile/security/api-tokens.
В репозитории он не хранится: только через переменные окружения.

## Правила доски

Статусы пришли из шаблона Jira и на русском: `К выполнению` → `В работе` →
`В процессе проверки` → `Готово`. Маппинг на цикл из `docs/sdlc.md`:

| Колонка | Что означает для CYBRA |
|---|---|
| К выполнению | задача в бэклоге, критерии сформулированы |
| В работе | есть ветка, идёт реализация |
| В процессе проверки | PR открыт, ждёт ревью и зелёный CI |
| Готово | критерии приёмки выполнены, код в `main` |

WIP-лимиты выставляются в UI доски (API создания колонок в новом Jira удалён).
Рекомендация: не больше 2 задач в `В работе` на человека и 3 в
`В процессе проверки`.

## Definition of Done

Задача считается готовой, когда:

1. код в `main` через PR;
2. прошёл ревью хотя бы одним человеком;
3. есть тесты на новую логику (для UI — проверка в браузере);
4. критерии приёмки из описания задачи выполнены;
5. статус `Готово`, а не «почти готово».

## Связь с GitHub

Тот же бэклог создан в GitHub Issues (`jira/github_import.py`), чтобы задачи
были видны у внешних контрибьюторов, которые не имеют доступа к Jira.
Соответствие: эпик Jira = issue с меткой `epic:<ключ>`, история Jira = issue с
меткой `story`.
